# Каскадный поиск: API и логика ответа

Каскад — основной режим распознавания. DINOv2 отбирает кандидатов, SigLIP 2 и DINOv2 вместе их ранжируют, а по сходству и отрыву от второго кандидата выбирается одна из трёх зон ответа. Как измерены точность и пороги — в [`RECOGNITION_QUALITY.md`](RECOGNITION_QUALITY.md).

## 1. Как работает

```text
Фото ─► YOLO: кроп этикетки в исходном разрешении
          ├─ вид A: letterbox 518×518 кропа
          └─ вид B: маска сегментации + letterbox 518×518
              │
              ▼
   DINOv2-small LoRA (384d): векторы A и B
   кандидаты = 30 вин, ближайших к усреднённому вектору (pgvector, лучший эталон на вино)
              │
              ▼
   SigLIP 2 LoRA (768d): векторы A и B
   для каждого кандидата: лучшее сходство с его эталонами по каждому виду и каждой модели
   оценка = SigLIP2(A) + SigLIP2(B) + 0,3 · (DINOv2(A) + DINOv2(B))
              │
              ▼
   близнецы: если в топ-3 вина одного производителя с отрывом оценки ≤ 0,15 —
   сравнение фото с их эталонами только в местах, где этикетки различаются → новый порядок
              │
              ▼
   similarity = SigLIP 2 лучшего кандидата, margin = отрыв оценки первого от второго (до этапа близнецов)
   similarity < 0,55                          → not_in_catalog  «Данного вина нет в каталоге»
   similarity ≥ 0,83 и margin ≥ 0,15          → found           «Вино найдено в каталоге»
   иначе                                      → probable        «Похоже на это вино — сверьте название, год и цвет»
```

OCR в каскаде не используется: на размеченных фото он не повышал точность и не отличал вина не из каталога.

### Этап близнецов

У некоторых вин одного производителя этикетки совпадают целиком, кроме мелкой детали: у «Фантом 30/70 / 50/50 / 70/30» (Ведерниковъ) это цветной квадрат с пропорцией и цифра крепости. Глобальные векторы DINOv2 и SigLIP 2 такую деталь не видят, и оценки близнецов почти равны. Этап (`app/services/twin_resolver.py`):

1. совмещает эталоны близнецов (SIFT + гомография) и находит компактные области, где они различаются;
2. совмещает с ними кроп этикетки с фото, находит каждую область по её окружению (с поправкой на сдвиг и масштаб — этикетка изогнута) и сравнивает цвет. Для сплошной области (квадрат пропорции) — медианный цвет: светлота и тон полностью, насыщенность с весом 0,25 (камера телефона меняет её сильнее всего). Для тонкого текста (красный год у «красного», серый у «белого») — оттенок чернил относительно бумаги: размытие маленьких фото каталога его не меняет;
3. ставит первым близнеца с наименьшим отличием, если оно хотя бы на 20 % меньше, чем у второго, и если тот же близнец выбирается при совмещении с первым и с последним эталоном; иначе порядок не меняется. Область голосует с весом, равным тому, насколько в ней различаются сами эталоны: место, где близнецы на фото каталога почти одинаковы, не решает ничего.

Пример тонкого текста — «Поздний сбор» (Литавщук): у красного год и слово «красное» напечатаны красным, у белого серым. На маленьком фото каталога красный год вышел почти коричневым и не различает вина; решает слово «красное», где оттенок эталона сохранился. Этап ничего не меняет, если эталоны близнецов — одно и то же изображение (в каталоге так хранятся, например, разные годы «Вионье» и «Ркацители»), разные фото одной этикетки (фоновое отличие эталонов > 2 или больше 4 областей различия), этикетки одной серии (эталоны совмещаются меньше чем по 80 точкам или различаются больше чем на 6 % площади) или фото не совмещается с эталоном. На 100 контрольных фото этап проверен против всех вин того же производителя (1498 пар): 8 верных выборов, ни одного неверного, остальное — отказ. Пороги и зоны ответа не меняются: margin считается до этапа близнецов, поэтому близнецы по-прежнему получают `probable`, меняется только выбранное вино. Вердикт этапа — в `decision.twin_resolution`, время — в `timings.twin_ms`. Этап запускается только для запросов с близнецами в топ-3. Подготовка эталонов кэшируется по паре вин, поэтому первое фото пары стоит 350–550 мс, следующие — 110–200 мс, отказ — около 90 мс (замеры на CPU разработчика). Скорость и эффект на сервере: `scripts/twin_timing.py` — из одного прогона показывает время с этапом и без него (`total_ms − twin_ms`).

OCR этап не использует: стандартный EasyOCR (ru + en) читает «красное» как «/раское» за 1,3 с на CPU и не читает повёрнутое «30/70» в квадрате «Фантома».

Если SigLIP 2 не загрузился, каскад работает только на DINOv2 (`stage_reached = "v1_only"`), и все ответы получают статус `probable`.

## 2. Эндпоинты

### `POST /api/cascade/search` — полный ответ с диагностикой

Поля формы: `image` (фото), `k` (число кандидатов в ответе, по умолчанию 5).

```bash
curl -X POST http://localhost:8030/api/cascade/search -F "image=@bottle.jpg" -F k=5
```

```json
{
  "status": "probable",
  "message": "Похоже на это вино — сверьте название, год и цвет с этикеткой",
  "confidence": 0.9284,
  "stage_reached": "fusion",
  "winner": {
    "product_id": "…", "slug": "belbek-belbek-roze-pino-nuar-rozovoe-suhoe-129",
    "title": "Бельбек Розе", "manufacturer": "Бельбек", "description": "…",
    "image_url": "/api/media/products/…/label.webp",
    "v1_similarity": 0.9551, "v4_similarity": 0.9284, "fusion_score": 2.4271, "rank": 1,
    "dino_similarity": 0.9551, "final_score": 0.9284
  },
  "final_results": ["… до k кандидатов в том же формате …"],
  "decision": {"status": "probable", "similarity": 0.9284, "margin": 0.1021,
               "reason": "Близкий второй кандидат: отрыв 0.102 < 0.150",
               "twin_resolution": "Выбран по области различия близнецов: отличие 12.4 против 27.7"},
  "v1_results": ["… первичная выдача DINOv2 (SearchResult) …"],
  "timings": {"bbox_detect_ms": 27.5, "query_prep_ms": 35.3, "v1_total_ms": 183.4,
              "v4_total_ms": 49.6, "twin_ms": 238.1, "total_ms": 534.4},
  "bbox_crop": "data:image/webp;base64,…",
  "v4_query_crop": "data:image/webp;base64,…"
}
```

При `status = "not_in_catalog"` поле `winner` = `null`, а в `final_results` — самые похожие этикетки каталога (это другие вина, их можно показать как «похожие»).

`POST /api/cascade/search-from-crop` — то же для уже вырезанной этикетки (поле `crop`).

### `POST /api/cascade/predict` — ответ для автоматической проверки

Тот же ответ даёт `POST /api/cascade/eval/predict`; `POST /api/v1/eval/predict` возвращает тот же `slug`.

```bash
curl -X POST http://localhost:8030/api/cascade/predict -F "image=@26ddb066.jpg" -F "query_id=q-000001"
```

Ответ содержит поля строки `predictions.jsonl` из золотого набора (`query_id` — из необязательного поля формы, `image_path` — имя загруженного файла) и поле `slug`, которое читает `participant_test.sh`:

```json
{"query_id": "q-000001", "image_path": "26ddb066.jpg", "image_sha256": "26ddb066cb40c88571ccd0703e892a0fd86eef140b215f91e3adbe0179e55107", "predicted_slug": "agora-muskat-chernyj", "latency_ms": 312.5, "slug": "agora-muskat-chernyj", "status": "found", "stage_reached": "fusion", "confidence": 0.865}
{"query_id": null, "image_path": "bottle.webp", "image_sha256": "367a651c…", "predicted_slug": null, "latency_ms": 628.4, "slug": null, "status": "not_in_catalog", "stage_reached": "fusion", "confidence": 0.2532}
```

В ответе проверки два статуса: `found` (вино определено, `slug` — ответ) и `not_in_catalog` (`slug` = `null`). Зона «похоже» сканера здесь отдаётся как `found` с тем же `slug`; три зоны — только в `/api/cascade/search` и в интерфейсе. Необязательное поле формы `threshold` (или настройка `CASCADE_PREDICT_THRESHOLD`) дополнительно отклоняет ответы со сходством SigLIP 2 ниже заданного.

### `GET /api/cascade/thresholds` — пороги, с которыми работает сервер

```json
{"found_min_similarity": 0.83, "found_min_margin": 0.15, "reject_below_similarity": 0.55,
 "predict_threshold": null, "candidate_pool": 30, "v1_weight": 0.3, "stage": "fusion"}
```

Сканеры показывают эти пороги рядом с ответом. Меняются они в `.env` (раздел 3) и применяются после перезапуска; порог «нет в каталоге» не может быть выше порога «найдено» — иначе API не стартует.

### Сомелье к результату распознавания

- `GET /api/sommelier/wine/{slug}?dish=…` — справка о вине и, если передано блюдо, оценка сочетания.
- `GET /api/sommelier/wine/{slug}/alternatives?limit=5` — похожие по стилю вина каталога: тот же цвет и игристость, сладость отличается не больше чем на ступень, затем сорт, тип, тело, танины, ароматика и регион; не больше двух вин одной винодельни. У каждой альтернативы — доводы из карточки и картинка этикетки.

## 3. Настройки (`.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `CASCADE_CANDIDATE_POOL` | 30 | сколько кандидатов DINOv2 передаёт на SigLIP 2 |
| `CASCADE_V1_WEIGHT` | 0.3 | вес DINOv2 в итоговой оценке |
| `CASCADE_FOUND_MIN_SIMILARITY` | 0.83 | минимальное сходство SigLIP 2 для ответа «найдено» |
| `CASCADE_FOUND_MIN_MARGIN` | 0.15 | минимальный отрыв от второго кандидата для «найдено» |
| `CASCADE_REJECT_BELOW_SIMILARITY` | 0.55 | ниже этого сходства — «нет в каталоге» |
| `CASCADE_PREDICT_THRESHOLD` | не задан | дополнительный порог отказа для `/predict` |
| `ENABLE_CASCADE_TWIN_RESOLVER` | true | этап близнецов |
| `CASCADE_TWIN_MAX_GAP` | 0.15 | максимальный отрыв оценки, при котором вино того же производителя считается близнецом лидера |
| `CASCADE_TWIN_POOL` | 3 | сколько первых кандидатов проверяется на близнецов |

Вина, добавленные формой `/add`, `POST /api/products` или пакетом `POST /api/imports` (в манифесте можно указать `slug`), получают те же эталоны, что и основной каталог: YOLO-кроп → letterbox 518 → 116 аугментаций → векторы DINOv2 и SigLIP 2. Поэтому они сразу распознаются с этими порогами.

Пороги откалиброваны на 164 размеченных фото. После изменения каталога их нужно пересчитать: `scripts/research_dump_features.py` → `scripts/calibrate_cascade.py`.

## 4. Веб-интерфейс

`http://<сервер>:8030/search-cascade`:

- цветной статус ответа (найдено / похоже / нет в каталоге) с причиной и таймингами;
- оригинал → кроп → вино из каталога;
- AI-сомелье: справка «о вине и с чем подать», похожие вина-альтернативы; если вина нет в каталоге — вопрос к сомелье;
- кандидаты с оценками обеих моделей и первичная выдача DINOv2;
- «Мой набор»: проверка папки фото по списку `queries.tsv` / `labels.tsv` / `mapping.json` (включая вина не из каталога) с точностью, зонами ответа и выгрузкой `predictions.jsonl` / `results.tsv`.

Мобильные сканеры показывают тот же статус и альтернативы сомелье. Основной — `/mobi/` в дизайне «Своё Вино»: карточка вина (категория, регион, сорт из карточки сомелье), оценка бокалами, сомелье «к мясу / рыбе / сырам» и своё блюдо, чат, другие кандидаты при «похоже» и похожие этикетки при «нет в каталоге». Все сканеры отправляют на сервер полный кадр или исходное фото: этикетку вырезает серверная YOLO, на её кропах откалиброваны пороги.
